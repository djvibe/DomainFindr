# Domain Research Lessons

This document captures durable lessons from real domain strategy sessions so future work can start from a stronger baseline.

## Naming Strategy Lessons

### Exact-match `.com` availability is rare for strong names

For short, clean, startup-grade names, assume the best `.com` domains are likely taken.

Implications:

- do not over-anchor on exact-match `.com`
- search premium alt TLDs early
- keep fallback paths ready before getting emotionally attached to one name

### Alternative TLDs can be better than weak `.com` compromises

Strong exact-root names on `.ai`, `.io`, `.co`, `.spa`, or `.wellness` are often better than awkward prefixed or stretched `.com` domains.

Examples of stronger fallback types:

- `spaatlas.ai`
- `sparank.ai`
- `spascout.io`

Examples of weaker fallback types:

- `getspaatlas.com`
- `tryspaatlas.com`
- `joinspaatlas.com`

### Descriptive brands and premium brands serve different jobs

Names like `AllSpas` are strong for:

- directory clarity
- SEO
- category understanding

Names like `Wellsy` are stronger for:

- company brand
- software/platform positioning
- long-term brand value

Do not force one name to do both jobs if a two-brand structure makes the strategy cleaner.

### Legal entity names and market-facing brands should be evaluated separately

Formal names like `Cascade Wellness Technologies` may work well for:

- legal entity
- contracts
- banking
- admin

They are usually weaker as:

- consumer brand
- software product brand
- premium company identity

## Availability Research Lessons

### Registrar checkout beats RDAP for buying decisions

RDAP is useful for broad screening, but it is not enough for final purchase decisions.

Important edge cases:

- premium marketplace listings
- broker-only domains
- TLD-specific registry rules
- registrar-specific restrictions

If RDAP says a domain is available but registrars show it as premium or unavailable, trust the registrar checkout.

### Premium listings change the recommendation materially

If a domain is technically obtainable only through a high premium acquisition price, treat it as a different class of option.

Example:

- `wellsy.co` showed as effectively unavailable for normal registration because registrars treated it as unavailable or premium

That means:

- it should not be grouped with standard hand registrations
- it should trigger a budget/value discussion before it stays on the shortlist

### Broad TLD sweeps are useful, but only a subset are serious options

Large sweeps are helpful for discovery, but consultant output should narrow quickly to:

- premium startup TLDs
- category-relevant TLDs
- country-code TLDs that match the market
- clean backup options with credible resale value

Avoid overwhelming users with low-signal fringe TLDs.

## Workflow Lessons

### Batch file format matters

Markdown input must be constrained to domain-bearing structures only.

Safe formats:

- fenced code blocks with one domain per line
- markdown tables with a `domain` column
- bullets containing domains
- CSV with a `domain` column or first-column domain list

Avoid prose mixed directly with raw domain lines.

### Domain strategy output should have two levels

Every strong session should end with:

1. a short executive summary
2. a full research report

This makes future review faster and improves continuity across sessions.

### Consultant-style work should move beyond availability checking

The most useful outcomes are not just:

- available / taken

They also include:

- brand role
- strategic fit
- fallback class
- recommendation by use case
- next-step purchase guidance

## Recommended Default Shortlist Structure

For future domain strategy sessions, rank candidates into:

1. best startup / software brand
2. best directory / media brand
3. best authority / ranking brand
4. best clean `.com`
5. best wildcard or coined brand

This gives a clearer decision frame than a flat list of available names.
